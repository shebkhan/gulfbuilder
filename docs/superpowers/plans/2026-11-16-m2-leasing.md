# M2 Leasing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tenants, leases and lease charge schedules in the hosted database, with the web UI to create, activate, terminate and renew a lease — following the three foundation rules.

**Architecture:** All state transitions and money arithmetic live in SQL functions (Rule of location, D-010). ID numbers are encrypted by `encrypt_id`/`decrypt_id` reading a Vault key (D-011). Next.js server actions only parse input, call an RPC, and revalidate. A pure TypeScript planner mirrors the SQL schedule so the UI can preview charges before activation and so Vitest can pin the arithmetic without a database.

**Tech Stack:** Postgres 15 (Supabase), plpgsql, pgcrypto, Supabase Vault, Next.js 15 App Router, Server Actions, next-intl, Vitest.

**Spec:** `docs/SPEC.md` §5.3, §7.1–7.3, §7.6, §13 criteria 3 and 6; `docs/superpowers/specs/2026-11-16-mobile-ready-foundation-design.md`

## Global Constraints

- Money is `bigint` minor units plus `char(3)` currency. Never a float, never a bare number in the UI. Format with `formatMoney` (`src/lib/money.ts`).
- Every table gets `org_id uuid not null`, RLS enabled, and policies keyed on `auth_org()` / `auth_role()` (`0007_auth_fallback.sql`).
- Migrations are append-only. New files are `supabase/migrations/20261116000009_*.sql` upward; never edit an applied migration.
- Every user-visible string goes through next-intl in both `messages/en.json` and `messages/ar.json`. Arabic must read naturally, not word-for-word.
- CSS is logical only: `ms-`/`me-`, `ps-`/`pe-`, `border-s`/`border-e`, `start-`/`end-`. No `left`/`right`.
- Server actions re-check the capability with `can(ctx.role, …)` from `src/lib/rbac.ts`; the database checks it again.
- Roles: `org_admin`, `manager` write leases (`leases.write`); `org_admin` approves sub-lets (`leases.approve`). `accountant`, `caretaker` read. `owner` sees buildings they own; `tenant` sees their own lease only.
- pgTAP is not run (D-008). Verification is a rolled-back SQL probe through Supabase MCP plus Vitest.
- Never start a dev server; port 3000 belongs to the owner. Never run `pnpm build` while that server is up.

## Review Focus

1. **A second lease on an occupied unit.** Two managers submit at the same time; the exclusion constraint and the trigger must reject exactly one, and the losing form must show a readable message, not a 500.
2. **Re-running activation.** Pressing "activate" twice, or retrying after a timeout, must not duplicate charges or fail; `(lease_id, type, period_start)` is the guard.
3. **Rent that does not divide evenly.** 1,000.00 over 3 installments must total 1,000.00, with the remainder on the last charge — not 999.99 or 1,000.02.
4. **A caretaker or owner opening a lease URL they have no right to.** RLS returns no row; the page must 404, not leak the tenant's name or phone in an error.
5. **Arabizi in a tenant name.** A name with Arabic, Latin, digits and an apostrophe (`Al-Kuwari's Sons`) must round-trip through form → action → table → display unchanged, and RTL must not reorder the Latin part.

**Interfaces:**
- Produces: `public.encrypt_id(plaintext text) returns text`, `public.decrypt_id(ciphertext text) returns text`, `public.tenant_id_number(p_tenant uuid) returns text`, `maskId(value: string): string`

- [ ] **Step 1: Provision the Vault secret once, outside git**

Run via Supabase MCP (`execute_sql`), generating a fresh 32-byte base64 key locally first:

```sql
select vault.create_secret('<base64-key>', 'id_encryption_key', 'tenant ID number encryption');
```

Expected: one row id. The key must never appear in a migration, in `.env.local`, or in a commit.

- [ ] **Step 2: Write the migration**

Functions: `encrypt_id` is `volatile security definer set search_path = public, extensions` and returns `encode(pgp_sym_encrypt(p_plaintext, v_key, 'cipher-algo=aes256'), 'base64')`. `decrypt_id` is `immutable` in intent but reads Vault, so declare it `stable security definer`. Both read the key with `select decrypted_secret from vault.decrypted_secrets where name = 'id_encryption_key'` and `raise exception 'id key missing'` when null.

`tenant_id_number(p_tenant uuid)` is `stable security definer`, resolves the tenant's `org_id` and `user_id`, then allows the call only when the caller is `auth_role() in ('org_admin','manager','accountant')` inside `auth_org()`, or when `tenants.user_id = auth.uid()`, or for the lease-owning tenant. Otherwise `raise exception 'not authorised' using errcode = '42501'`.

Revoke all on both helpers from `authenticated`; grant execute on `tenant_id_number` only.

- [ ] **Step 3: Apply and probe**

```bash
supabase db push --linked
```

Rolled-back probe: as `org_admin`, `decrypt_id(encrypt_id('28863451234')) = '28863451234'`; the ciphertext contains no digit of the plaintext; calling `tenant_id_number` as `caretaker` raises `42501`.

- [ ] **Step 4: Move `maskId`, delete the old module**

`maskId` returns `'••••' + last4` for values of 4+ characters, `'••••'` otherwise. Copy the existing test expectations from `rbac.test.ts` into `mask.test.ts`, then delete the crypto assertions and the module.

- [ ] **Step 5: Verify and commit**

Run: `pnpm typecheck && pnpm test`
Expected: clean, all tests pass with the new `mask.test.ts` and no crypto import.


### Task 6: `terminate_lease` and `renew_lease`

**Files:**
- Create: `supabase/migrations/20261116000013_lease_lifecycle.sql`

**Interfaces:**
- Produces: `terminate_lease(p_lease uuid, p_date date, p_reason text) returns void`, `renew_lease(p_lease uuid, p_terms jsonb) returns uuid` (new draft lease id).

- [ ] **Step 1: Implement termination**

`org_admin`/`manager` only. Sets `status = 'terminated'`, `terminated_at`, `termination_reason`. Voids unpaid future charges (`status = 'void'` where `due_date > p_date` and `paid_minor = 0`); leaves paid charges alone. `derive_unit_status` then frees the unit.

- [ ] **Step 2: Implement renewal**

Creates a new `draft` lease copying the old one's `unit_id`/`room_id`, `tenant_id`, `currency`, `notice_days`, with `start_date`, `end_date`, `rent_minor`, `payment_frequency`, `installments`, `due_day`, `deposit_minor` taken from `p_terms`. Sets the old lease `status = 'renewed'` only when the new one's `start_date` equals the old `end_date`. Returns the new id. Does not generate charges — activation does.

- [ ] **Step 3: Probe**

Terminate mid-term → future rent charges void, paid charges untouched, unit `vacant`, second termination raises. Renew → new draft with the same unit, old lease `renewed`, activating the new one generates a fresh schedule with no collisions.

- [ ] **Step 4: Commit**

```bash
git add -A && git commit -m "feat(db): terminate_lease and renew_lease"
```
